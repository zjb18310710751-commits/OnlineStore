# 五项质量属性改进设计与执行计划

基线：4bfdc48；用户已要求实施五项属性提升，并补齐证据、恢复演示、SQL工具、CI及报告。本轮以课程最高档的“清晰、深入、相互结合”描述为目标，不保证评分或绝对无缺陷。

## 设计选择

沿用.NET 8 MVC、单应用和SQL Server。选择可验证的模块化改进：故障时明确503并保留安全边界、健康检查区分进程与依赖、订单物流策略独立、交互可用键盘且轮询故障可恢复、把验证工具与CI纳入源码。保留事务和归属校验。

只补说明文档无法补足运行证据；增加多服务器和新数据库会改变课程项目的部署前提，当前采用最小、可在本机重复验证的方案。这是实施判断，不声称用户选择过未展示的选项。

## 执行与验收

- [x] Availability：共享数据库故障响应(503、Retry-After、无内部异常)，存活/就绪探针；隔离数据库断开再恢复，记录响应、恢复时间与数据完整性。
- [x] Security：只信任明确代理，账号敏感请求按来源限速、无排队；安全响应头；真实HTTP验证429、伪造来源不能绕过限制、错误不泄露信息。无写操作自动重试。
- [x] Modifiability：抽出纯物流策略与不可变输入/输出，以替代策略测试证明变更隔离；订单事务仍由原服务掌管。
- [x] Testability：仓库内SQL验证入口，拒绝已有日常库；独立CI覆盖Ethan-Yang/HUZHANHAO/main及PR，保留可下载测试结果；不需要生产密钥。
- [x] Usability：下拉框键盘与错误焦点；订单更新网络失败/恢复双语反馈，避免后台刷新打断正在操作的用户；Node及实际浏览器验证。
- [x] 文档：每属性记录刺激、环境、响应、度量、代码、命令、实际结果与限制；记录跨属性权衡；更新三图与报告，个人反思/贡献仍需学生真实填写。
- [x] 总验收：全套.NET/Node、真实SQL、故障恢复、发布、浏览器；本机配置哈希不变，验证工具不写日常数据库；独立复核。

## 重点失败场景

数据库故障不应诱发重复下单；响应已开始时不得覆盖输出；伪造X-Forwarded-For不能重置限速桶；一名用户的操作焦点不能被订单刷新夺走；SQL工具误传日常数据库必须在写入前拒绝。各项测试必须报告真实结果，不能用自定目标冒充已测量结果。
