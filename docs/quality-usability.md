# Usability：键盘操作与订单更新恢复

验证日期：2026-10-29（Europe/London）。本轮针对共享组件的真实缺口，保留既有外观、表单提交及订单自动更新功能。组件改动未改变数据库结构、账号权限或订单业务规则。

## 改动与使用效果

| 位置 | 原有问题 | 当前行为 |
| --- | --- | --- |
| `wwwroot/js/site.js` 自定义单选框 | Home/End 可能停在禁用占位项；菜单恰好展开在静止鼠标下方时，mouseenter 会覆盖键盘高亮 | Home/End 找到首尾可用项；实际指针移动才更新高亮；Enter 提交，Escape 取消，Tab 退出 |
| 同一共享单选框 | 原控件的显式 ARIA 名称可能被当前选项文本替代；必填失败时浏览器可能聚焦隐藏的原生 select | 保留 aria-labelledby / aria-label 的命名优先级及错误描述；聚焦可见 combobox，显示本地化验证信息；选择有效内容后清除错误 |
| `wwwroot/css/site.css` | 新增错误提示作为 flex 子项会挤压选择控件 | 共享容器使用纵向排列，错误位于控件下方；正常状态保持原尺寸和样式 |
| `wwwroot/js/customer-order-updates.js` | 网络失败、HTTP 503、登录过期没有可见说明 | 显示中英恢复提示及操作按钮；503 和普通网络失败保持自动重试；401/403/重定向停止轮询并提供重新加载 |
| 同一订单轮询组件 | 状态更新可能在按钮、链接或自定义 combobox 聚焦期间重载，打断键盘操作 | 有弹窗、原生输入、内容编辑区或交互控件焦点时延后重载；显示“立即刷新”；用户可主动刷新 |
| 同一订单轮询组件 | 简单清空错误可能让仍聚焦的重试按钮消失 | 恢复时保留聚焦按钮并显示“实时更新已恢复”；焦点移开后清除提示，不主动移动用户焦点 |

状态信息使用已有 `ui-inline-feedback`、`ui-button` 风格及 `role="status"`、`aria-live="polite"`。重复失败不会在每一轮重复改写相同提示文本。服务提供数字秒数的 `Retry-After` 时，自动请求等待该时长（最高 60 秒）；用户显式重试可立即检查。未添加第三方前端依赖。

## 五项质量属性如何配合

| 属性 | 此改动的联系与取舍 |
| --- | --- |
| Availability（可用性） | 临时服务故障保留当前页面，并说明数据可能过时；服务恢复可继续更新。它改善故障期间的可理解性与恢复路径，不提供数据库故障转移。 |
| Modifiability（可修改性） | 通用选择行为集中在已有共享组件；轮询恢复文案集中为中英消息集合，复用已有反馈样式；没有逐页复制一套 UI。 |
| Testability（可测试性） | Node 测试直接执行真实共享脚本，通过受控 DOM/网络边界检查选择、焦点与恢复行为；另用真实浏览器补足鼠标布局事件与 CSS 排版的盲点。 |
| Usability（易用性） | 使键盘任务可完成、错误可发现、后台刷新不会立即夺走操作上下文；反馈提供具体下一步。自动重载因焦点暂缓时，用户会看到数据已更新的提示。 |
| Security（安全性） | 认证失效停止无意义轮询，重新进入正常登录流程；错误文案来自本地消息集合并使用 textContent，不渲染服务端异常 HTML；保留既有同源凭据及后端授权边界。前端反馈不替代服务端鉴权。 |

## 验证证据

`node --test OnlineStore.Tests/Frontend/*.test.cjs`：本轮最终执行 **42/42 通过**，包含原有 29 项和新增 13 项。新增缺口先观察 RED，再修改生产代码至 GREEN；Escape/Tab 的已有正确行为作为回归保护。

重点回归：

- Home/End 跳过禁用项，选项只触发一次 change；静止鼠标不覆盖键盘选择。
- 显式可访问名称、aria-labelledby 优先级、原错误描述被保留；必填失败聚焦可见控件，有效选择清除反馈。
- 503 可重试并在成功后清除；中文网络失败提示不移动焦点；会话过期停止请求并允许重新加载。
- Retry-After 为 5 秒时，后续 4 个一秒 tick 不请求，第 5 秒继续；聚焦恢复按钮不会突然被隐藏。
- 原有订单未变化不重载、状态变化重载、编辑中暂缓、隐藏标签暂停、过期会话停止仍通过。

浏览器组件验证使用统一 `mcp__cua_repl`，页面为 `http://127.0.0.1:5119/` 的本地夹具，加载项目真实 `site.js`、`validation-messages.js`、`customer-order-updates.js` 及共享 CSS，以受控 HTTP 响应模拟订单状态。**它不运行 ASP.NET 控制器或 SQL Server，不能当作真实订单端到端验证。**

## 实际应用页面验证

2026-10-29 的统一集成验收使用发布版本 `http://127.0.0.1:5097` 和隔离验证数据库，通过 `mcp__cua_repl` 检查真实 ASP.NET 页面。目录排序控件通过 End、Enter 完成选择；买家订单页面在测试数据库断开后自动显示 `Retry now`，原订单内容仍可见；数据库恢复 ONLINE 后提示自动消失。390×844 手机视口中，订单图片、总价和操作按钮可见。此结果补充上述组件夹具，不能扩展为全站所有浏览器均已验收。

## 边界与后续验收

本轮未进行真实用户实验、屏幕阅读器人工朗读验证或完整 WCAG 审计，不能据此宣称 WCAG 全符合或量化用户满意度提升。未覆盖所有手机尺寸、浏览器、动态增删选项及隐式 label 场景。后台管理员的独立轮询脚本没有扩展此恢复 UI。

本轮实际页面验收覆盖目录排序和买家订单故障恢复；结账的全部提交分支、所有语言切换、全部权限组合及其他移动设备仍可继续扩展。订单状态变化采用整页重载，有交互焦点时暂缓；当前机制没有实现所有未提交草稿的持久化。普通网络异常继续按现有一秒周期轮询，收到数字 Retry-After 才延后自动请求。
